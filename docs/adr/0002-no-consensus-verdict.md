# 不对两家的差异下聚合结论

曾经在页面顶部做过一张"共识卡",把差异归纳成「高度一致 / 大体吻合 / 存在明显分歧」三档,并给分歧配了橙色警示。已删除,页面只呈现差异、不下结论。

## 为什么

**一、分歧是系统性常态,不是异常事件。** 两家跑的是**两套独立的预测系统**:和风主要基于 ECMWF 的中期模型加本地化修正,长处在中长期趋势和全球覆盖;彩云更依赖自建雷达网络和外推/AI 模型,长处在短临降水。它们对同一时刻大气状态的"理解"本就不同,更新节奏也不同。这意味着分歧几乎天天存在 —— 一个天天亮红灯的指示器不提供任何信息,只会训练用户忽略它。

**二、它违背了这个应用的核心命题。** `CLAUDE.md` 第一句就是"这个应用**不替用户选**,而是把两家的预报摆在一起,差异一眼可见"。三档判定是在替用户下结论;更糟的是"高度一致"会被读成"可信度高",而一致完全可能只是两家在这个变量上恰好同源,与准确性无关。

**三、它的信息全是冗余的。** 实况温差在 `headline` 两个大温度里、降水判定不同在天气文案和图标里、某时刻的降水分歧在曲线的概率柱里、逐日差异在两张卡片并排的温度数字里。这张卡是用一个不该下的结论,重述已经呈现过的事实。

同一个理由也删掉了逐日行上的一致性色条(`high`/`moderate`/`low` 的黄橙左边框)—— 它是同一类评级,橙色同样把常态渲染成"这天有问题"。

## 一并否决的替代方案

**按强弱项给使用引导**(如"短临降水看彩云、中长期趋势看和风")。这比三档判定更彻底地替用户选了,而且流传的那些准确率数字(某家 91%、某家 87.5% 之类)无法从两家的公开文档核实。把未经验证的论断固化成产品主张,比不给结论更糟。定性的机理差异适合写在这里供维护者理解,不适合写进界面当作对用户的建议。

## Consequences

`frontend/src/utils/align.ts`(原 `consensus.ts`)现在只做逐时的时间戳对齐,不含任何判定逻辑。`alignDaily` 随色条一起删除 —— 它唯一的消费者就是那个色条。

如果将来要重新引入某种"帮用户理解差异"的功能,先回答一个问题:它是在**呈现**差异,还是在**评价**差异?前者(例如"两条曲线在 18:00 相距最远")与产品命题一致;后者(例如"分歧显著,建议谨慎参考")不一致。
